# HSK 독해 탭 설계서

- 작성: 2026-10-12
- 대상 회차: HSK 3급 공식 모의고사 H31001~H31005 독해 41~70번 (회차는 계속 추가할 수 있게)
- 앞선 설계: `2026-10-09-hsk-listening-tab-design.md` (듣기 탭)

## 목적

11/7 HSK 3급 시험 전에 독해 30문항을 회차별로 풀고, 틀리거나 모른 문항은 정답만 확인하는 데서 그치지 않고 «왜 그 답인지»와 «문장이 어떻게 짜였는지»를 해설서처럼 읽으며 공부한다.

## 성공 기준

- 회차·부분을 고르면 문항 하나씩 «읽기 → 답 고르기(또는 모르겠음) → 정답·해설 확인»을 할 수 있다.
- 풀 때는 시험처럼 한자만 보이고, 필요하면 «병음 보기»로 병음을 켤 수 있다.
- 문항마다 해설에 ① 정답 근거 ② 오답 이유 ③ 문장 끊어 읽기(성분) ④ 단어(품사·뜻·용법·예문) ⑤ 문법(패턴·설명·예문)이 있다.
- 지문·보기 전체에 한글 해석과 한자 아래 병음이 붙는다.
- 독해 핵심 단어가 단어장·랜덤 학습에 «HSK3 독해» 단원으로 들어간다.
- 듣기 탭은 겉보기와 동작이 그대로다.

## 화면 (독해 탭)

- 탭 줄 끝에 «독해»를 추가한다.
- 회차 칩(H31001…), 부분 칩(전체/1/2/3), 회차별 «맞힘·틀림·모름», 이전·다음.
- 문항 카드: 번호·부분·유형 안내, «병음 보기» 토글, 지문, 보기, «모르겠음».
  - **1부분(41~50) 문장 짝 맞추기**: 문항 문장 + 묶음 보기 문장 A~F(41~45) / A~E(46~50) 버튼. 예시에 쓰인 보기는 흐리게 «예시» 표시하고 고를 수 없다.
  - **2부분(51~60) 빈칸 채우기**: 빈칸 문장(56~60은 A·B 대화) + 묶음 단어 보기 A~F. 예시 단어는 흐리게, 고를 수 없다.
  - **3부분(61~70) 짧은 글**: 지문 + ★ 질문 + A·B·C.
- 답을 고르면 정답·오답을 표시하고 병음·해석을 열고 해설을 펼친다. «해설 보기»로 고르지 않고도 펼칠 수 있다.
  - 1부분: 짝지어진 두 문장을 대화 순서대로 이어 보여 준다.
  - 2부분: 빈칸에 정답 단어를 채워 강조한 완성 문장을 보여 준다.
- 해설 순서: 정답 근거 → 오답 이유 → 끊어 읽기 → 단어 → 문법.
- 풀이 기록은 localStorage `sungmi-vocab-reading-v1`에 `{ "H31001": { "63": "C", "64": "?" } }`, 화면 상태(회차·부분·문항·병음 보기)는 `sungmi-vocab-reading-prefs-v1`.

공용 조각으로 옮길 때 지금 듣기 탭의 CSS 클래스 이름은 그대로 둔다. 독해에만 있는 요소는 `read*` 클래스로 새로 만든다.

회차 데이터:

```json
{ "id": "H31001", "title": "HSK 3급 H31001",
  "parts": [{ "part": 1, "guide": "서로 이어지는 문장 짝 찾기" },
            { "part": 2, "guide": "빈칸에 알맞은 단어 고르기" },
            { "part": 3, "guide": "짧은 글을 읽고 질문에 답하기" }],
  "groups": [
    { "id": "41-45", "part": 1,
      "options": [{ "label": "A", "words": [["太","tài"],["好","hǎo"],["了","le"]], "ko": "잘됐다!" }],
      "example": { "label": "E", "words": [["你","nǐ"]], "ko": "…" } }
  ],
  "items": [ … ] }
```

문항:

```json
{ "no": 63, "part": 3, "group": null, "answer": "C",
  "lines": [{ "speaker": null, "words": [["我","wǒ"],["对","duì"]], "ko": "나는 여기가 아주 만족스럽다…" }],
  "question": { "words": [["使","shǐ"]], "ko": "그를 만족스럽게 한 것은:" },
  "options": [{ "label": "A", "words": [["没有","méiyǒu"],["花园","huāyuán"]], "ko": "정원이 없다" }],
  "pair": null,
  "explain": {
    "basis": { "quote": "虽然没有花园，但是离河边很近", "note": "虽然…但是…에서 말하는 사람의 평가는 但是 뒤에 있다…" },
    "distractors": [{ "label": "A", "note": "虽然 쪽, 아쉬운 점이지 만족 이유가 아니다" }],
    "breakdown": [{ "chunks": [{ "text": "我", "role": "주어" }, { "text": "对这儿", "role": "부사어" }, { "text": "很满意", "role": "술어" }],
                    "note": "对 + 대상 + 满意 = '~에 만족하다'" }],
    "vocab": [{ "hanzi": "满意", "pinyin": "mǎnyì", "partOfSpeech": "형용사", "meaningKo": "만족하다",
                "usage": "对A很满意 / 对A不满意",
                "example": { "zh": "我对这个房间很满意。", "words": [["我","wǒ"]], "ko": "나는 이 방이 아주 마음에 든다." } }],
    "grammar": [{ "pattern": "虽然A，但是B", "note": "'A이긴 하지만 B'. 말하는 사람의 무게는 B에 있다.",
                  "example": { "zh": "虽然很贵，但是很好吃。", "words": [["虽然","suīrán"]], "ko": "비싸긴 하지만 맛있다." } }]
  } }
```

- `lines`: 1부분은 문항 문장 한 줄, 2부분은 빈칸 문장(대화면 `speaker` `A`·`B` 두 줄), 3부분은 지문 문장들. 2부분 빈칸 줄에는 `"blank": 단어 인덱스`가 붙고 그 자리 단어는 정답 단어다(풀기 전에는 화면이 «（　）»로 가린다).
- `group`: 1·2부분은 묶음 id(`41-45`), 보기는 묶음의 `options`를 쓴다. 3부분은 `null`이고 문항의 `options`를 쓴다.
- `pair`: 1부분만. `"item-first"` 또는 `"option-first"` — 짝지은 두 문장을 대화로 보여 줄 순서.
- `breakdown.chunks.role`: 주어·술어·목적어·관형어·부사어·보어·접속사·개사구 중에서 쓴다.
- «모르겠음»은 데이터에 없고 화면에서 붙인다.

## 처리 과정 (tools/reading)

중간 파일은 Google Drive 밖 `~/hsk-reading-work/<회차>/`에 둔다. 시험지 PDF는 듣기 때 받아 둔 `~/hsk-listening-work/src/<회차>.pdf`를 쓴다.

1. **paper**: PDF 텍스트(`pdftotext -layout`)에서 `二、阅读`~`三、书写` 구간과 答案의 41~70번을 뽑아 `paper.json`을 쓴다. 묶음(보기·예시), 문항 문장, 빈칸 위치, 대화 화자, 3부분 지문·★ 질문·A·B·C를 나눈다. 숫자·한자 사이 공백은 듣기 `tidy`와 같은 규칙으로 걷는다. 3부분 예시(例如) 지문은 화면에 쓰지 않는다. 검사: 문항 41~70 30개, 정답 30개, 1부분 묶음 보기 수(6·5), 2부분 단어 6개·빈칸 문항마다 1개, 3부분 보기 3개·질문 있음, 정답이 예시 보기가 아님.
2. **enrich**: 회차마다 `enrich.json`에 병음·해석·해설을 쓴다(Claude). 회차별로 나눠 병렬로 쓴다.
3. **review**: 다른 에이전트가 회차마다 해설을 읽고 정답 근거가 정답표와 맞는지, 오답 이유가 지문과 어긋나지 않는지, 문장 성분 표시가 맞는지 확인해 고칠 목록을 낸다. 고친 뒤 다음 단계로 간다.
4. **assemble**: paper와 enrich를 합쳐 `public/reading/<회차>.json`, `src/data/reading-index.json`을 쓰고, 단어장에 «HSK3 독해» 단원을 넣는다. 쓰기 전에 기계 검사를 한다.
   - 단어 묶음의 한자를 이으면 원문과 정확히 같다(지문·질문·보기·묶음 보기). 2부분은 빈칸 단어를 «（）»로 바꾼 결과가 원문과 같고, 빈칸 단어가 정답 보기 단어와 같다.
   - `breakdown.chunks`를 이으면 그 문항 화면에 나오는 문장(지문·질문·보기·짝 문장) 가운데 하나의 일부와 같다.
   - `distractors`의 보기 이름은 존재하고 정답이 아니다. 3부분은 나머지 두 보기가 모두 있다.
   - 필수 해설 칸이 비어 있지 않다. 예문 한자를 이으면 `zh`와 같다.
   - `pypinyin`과 음절이 다른 단어를 목록으로 뽑아 사람이 본다(다음자·변조는 맞을 수 있다).
   - 단어장에는 이미 어느 단원에든 있는 단어는 넣지 않는다. 예문은 그 단어가 나온 시험 문장으로 한다. 다시 돌리면 «HSK3 독해» 단원만 지우고 새로 넣는다. `lessons.js`의 `LESSON_ORDER`에 `HSK3 독해`를 `HSK3 듣기` 뒤에 더한다.

## 해설 기준

- 원문 한자는 PDF 그대로 둔다. 추정해서 바꾸지 않는다.
- 병음은 듣기·단어장 관례를 따른다. 不·一 변조를 표기하고(`bú shì`, `yí ge`) 경성은 성조 없이 쓴다.
- **정답 근거**: 답을 가리키는 원문 구절을 그대로 인용하고, 그 구절이 왜 답이 되는지 단서(접속사의 무게, 질문·대답 짝, 지시어, 품사 자리, 호응 등)를 1~3문장으로 설명한다.
- **오답 이유**: 3부분은 나머지 두 보기를 모두, 1·2부분은 헷갈리기 쉬운 보기 1~2개를 한 줄씩. «지문에 없음», «반대 내용», «품사가 안 맞음»처럼 이유가 드러나게 쓴다.
- **끊어 읽기**: 문항당 1~2문장(정답 근거 문장 우선). 성분 단위로 끊고 역할을 붙인 뒤, 구조 요약 한 줄을 단다.
- **단어**: 문항당 3~6개, HSK 3급 수준 위주(HSK1 기초어는 뺀다). 품사·뜻·용법(자주 쓰는 짝, 호응)·새 예문 1개.
- **문법**: 문항당 1~3개, 접속사·구문 패턴 위주(虽然…但是…, 把자문, 被자문, 比 비교문, 결과보어, 방향보어, 一…就…, 越来越 등). 설명과 새 예문 1개.
- 해설은 한국어로, 짧은 문장으로 쓴다.

## 확인

- `paper.py`를 다섯 회차에 돌려 검사가 모두 통과하고, 정답이 PDF 정답표와 같다.
- `assemble.py` 기계 검사 통과, `pypinyin` 차이 목록을 훑어 고칠 것을 고친다.
- Drive 밖 복사본에서 `npm ci` → `vite build`가 통과한다.
- 브라우저(폰 폭 390px·데스크톱)에서 세 부분 문항을 각각 풀어 본다: 예시 보기 비활성, 병음 보기 토글, 정답·오답 표시, 해설 다섯 칸, 2부분 빈칸 채움, 1부분 대화 순서, 새로고침 뒤 기록 유지.
- 듣기 탭이 전과 같이 동작한다(문항 재생·되풀이·이어 듣기·대본·해설).
